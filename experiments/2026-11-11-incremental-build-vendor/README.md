# Whether an incremental build notices an edit to a vendored extension

*What it measures:* whether an incremental build of RSQLite recompiles `src/ext-http.o` after an edit to `src/vendor/extensions/http.c`.
That file is the vendored source that `src/ext-http.c` includes.
The record also measures whether the build recompiles once `src/ext-http.dd` lists the file,
and what the rule in `src/Makevars.deps` keeps of the compiler's dependency output when it regenerates `src/ext-http.dd`.

*When and on what:* 2026-11-11, at commit 3b7bea34 (RSQLite 3.53.3.9022), built in a fresh worktree.
Ubuntu 24.04.5 with R 4.5.3, GNU Make 4.3, GCC 13.3.0 behind ccache 4.9.1, and pkgbuild 1.4.8, plus clang 18.1.3 for step 8 only.
Method: [`run.sh`](run.sh), output in [`output.txt`](output.txt).

*What it supports:* [#836](https://github.com/r-dbi/RSQLite/issues/836).
The issue reports that an incremental build misses edits to the bundled extensions under `src/vendor/extensions/`.
It names the cause: the generated `src/*.dd` files drop `vendor` paths.

## Method

[`run.sh`](run.sh) builds the package in place into a temporary library, as a developer would, in eight steps:

1. A full build with `R CMD INSTALL --preclean`.
2. An edit to the vendored file, then `R CMD INSTALL`.
3. The vendored file added to `src/ext-http.dd` by hand, then `R CMD INSTALL`.
4. `src/ext-http.c` touched, so that the build regenerates `src/ext-http.dd`, then `R CMD INSTALL`.
5. A second edit to the vendored file, then `R CMD INSTALL`.
6. `pkgbuild::compile_dll()`, which `devtools::load_all()` calls, to settle its own compiler flags.
7. A third edit to the vendored file, then `pkgbuild::compile_dll()`.
8. The rule in `src/Makevars.deps`, run by `make` on the `-MM` output of GCC and of clang for `ext-http.c`.

Each edit appends a `#pragma message` line to the vendored file, so the compiler announces each time it compiles that file.
After each build, the script reports from the build log what was compiled and linked, and the time stamp of `src/ext-http.o`.
On exit it restores the files it edited and deletes `src/ext-http.o`, so that the next build compiles it from the restored source.

## Findings

**An edit to the vendored file does not rebuild `ext-http.o`, with `R CMD INSTALL` or with `pkgbuild::compile_dll()`.**
After the full build, the edit leaves `R CMD INSTALL` with nothing to do, so the installed package keeps the old object:

```text
2. Edit src/vendor/extensions/http.c, rebuild: R CMD INSTALL
  compiled: nothing
  linked: nothing
  ext-http.o modified: 2026-11-11 15:48:49.969512693 +0000
```

`pkgbuild::compile_dll()` recompiles only `cpp11.cpp`, which it regenerates through `cpp11::cpp_register()` on every call:

```text
7. Edit src/vendor/extensions/http.c again, rebuild: pkgbuild::compile_dll()
  regenerated: cpp11.dd
  compiled: cpp11.cpp
  linked: RSQLite.so
  ext-http.o modified: 2026-11-11 15:49:17.603013706 +0000
```

Its first call, in step 6, recompiled everything, `ext-http.c` included.
Its debug flags had changed the output of `R CMD config --all`, and with it `src/.Rconfig`, on which every listed object depends.

**Listing the vendored file in `src/ext-http.dd` is enough to rebuild `ext-http.o`.**

```text
3. Add src/vendor/extensions/http.c to src/ext-http.dd by hand, rebuild: R CMD INSTALL
  ...
  compiled: ext-http.c
  linked: RSQLite.so
  vendor/extensions/http.c:578:9: note: ‘#pragma message: experiment: edit 1’
  ext-http.o modified: 2026-11-11 15:49:00.267981271 +0000
```

**The next regeneration of `src/ext-http.dd` drops the vendored file again.**
Once `src/ext-http.c` is newer than `src/ext-http.dd`, make remakes the latter before it builds anything:
R's `.c.d` rule writes the compiler's `-MM` output to `src/ext-http.d`, and the rule in `src/Makevars.deps` filters it.
The result has lost the line added by hand, and the second edit, in step 5, is missed again with "compiled: nothing":

```text
4. Touch src/ext-http.c, rebuild: R CMD INSTALL
  regenerated: ext-http.dd
  ...
  src/ext-http.dd now:
    # Generated by Makevars.deps, do not edit by hand and do not add dependencies to system headers
    ext-http.o: \
      ext-http.c \
     /opt/R/4.5.3/lib/R/include/Rconfig.h \
     vendor/extensions/../sqlite3/sqlite3.h \
     vendor/sqlite3/sqlite3.h \
      .Rconfig
```

**With GCC, the filter in that rule reaches only some of the paths.**
The rule breaks the compiler's output at each space between two paths, which puts each such path on a line of its own.
Those lines are indented by two spaces, and the rule then deletes the ones that continue with `/`, a drive letter, `vendor` or `..`.
A path that starts one of the compiler's own continuation lines is not broken off, and keeps that line's indent.
Clang indents continuation lines by two spaces, so the filter deletes those paths too, and the result is the committed `src/ext-http.dd`.
GCC indents them by one space, so those paths survive, an absolute one among them:

```text
  gcc (Ubuntu 13.3.0-6ubuntu2~24.04.1) 13.3.0, output with the indent of each line:
    indent 0: ext-http.o: ext-http.c /opt/R/4.5.3/lib/R/include/R_ext/Visibility.h \
    indent 1: /opt/R/4.5.3/lib/R/include/Rconfig.h vendor/extensions/http.c \
    indent 1: vendor/sqlite3/sqlite3.h vendor/extensions/sqlite3ext.h \
    indent 1: vendor/extensions/../sqlite3/sqlite3.h
```

Under either compiler `vendor/extensions/http.c` is dropped, under GCC because it happens to sit mid-line.
The same filter lets absolute and vendored paths into `src/cpp11.dd`, which R's `.cpp.d` rule makes with `-M`, system headers included.
After step 6:

```text
  src/cpp11.dd: 721 lines, 265 absolute paths, 445 vendored paths; as committed: 11 lines, 0 absolute paths, 0 vendored paths
```

## Replicating

The driver needs bash, GNU make, GNU coreutils and GNU sed on Linux, and R with pkgbuild, the package's build dependencies and a compiler.
Step 8 uses `gcc` and `clang` as found on the `PATH`, and skips one that is missing.
On macOS the link detection, which looks for `-shared`, and `gcc`, which there is Apple's clang, would not work as written.

From the root of a checkout:

```sh
experiments/2026-11-11-incremental-build-vendor/run.sh
```

It takes about a minute with a warm ccache, and longer without, since steps 1 and 6 compile the whole package.
The driver overwrites any existing in-place build of `src/`, and the next normal build recompiles everything.
It is best run in a throwaway worktree, as the record itself was.
The record was measured at 3b7bea34.
Running it from a later commit on this branch prints that commit, with the same findings, since those commits change nothing under `src/`.
If a build fails, the driver prints the step, the log lines that report an error, and the tail of its log to stderr, restores the files it edited and exits.
Time stamps and paths differ between runs and machines.
The findings rest on what each step compiled, on the dependency files, and on the indents.
Step 1's list of regenerated `.dd` files depends on the time stamps of the checkout, so a first run from a fresh checkout may not list `cpp11.dd`.
That does not affect the findings.
